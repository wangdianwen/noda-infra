在 Plan 01 和 Plan 02 全部验证通过后执行 Mac 清理。

**步骤 1.1 — 前置确认（r4s 验证通过的最终检查）：**
- 确认 r4s Tunnel 正常: `curl -sf -o /dev/null -w "%{http_code}" https://class.noda.co.nz/api/health` — 预期 200
- 确认 r4s 备份正常: `ssh root@r4s 'docker exec noda-ops ls /tmp/postgres_backups/ | wc -l'` — 预期 >= 1
- 如果任一检查失败，停止此任务，不清理 Mac

**步骤 1.2 — 检查 Mac noda-ops 当前状态：**
- 检查: `docker ps -a --filter name=noda-ops --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"`
- 可能的状态：
  - Running — 需要停止
  - Exited — 已停止（Phase 58 可能已停止），跳过停止步骤
  - 不存在 — Phase 58 已删除（不太可能，但处理此情况）

**步骤 1.3 — 停止 Mac noda-ops 容器（per D-13，不删除）：**
- 如果容器状态为 Running: `docker stop noda-ops`
- 如果容器已停止: 跳过此步骤
- 验证停止: `docker ps -a --filter name=noda-ops --format "{{.Names}} {{.Status}}"`
- 预期输出: `noda-ops Exited (0) ...` 或类似

**步骤 1.4 — 验证 Mac 停止后 r4s 仍正常运行：**
- 验证 Tunnel（最关键，per RESEARCH Pitfall 6 — Mac Tunnel 停止不应影响 r4s）:
  - `curl -sf -o /dev/null -w "%{http_code}" https://class.noda.co.nz/api/health` — 预期 200
  - `curl -sf -o /dev/null -w "%{http_code}" https://auth.noda.co.nz/` — 预期 200 或 302
- 验证 r4s noda-ops 容器正常: `ssh root@r4s 'docker exec noda-ops supervisorctl status'` — 预期 cron 和 cloudflared 都 RUNNING

**步骤 1.5 — 记录 Mac 容器状态：**
- 最终状态: `docker ps -a --filter name=noda-ops --format "table {{.Names}}\t{{.Status}}\t{{.Image}}\t{{.Size}}"`
- 记录停止时间，供 Phase 62 参考清理
