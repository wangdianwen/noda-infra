  <name>Task 1: 构建 noda-ops 镜像并管道传输到 r4s</name>
  <files></files>
  <read_first>
    deploy/Dockerfile.noda-ops
    docker/docker-compose.yml
    docker/docker-compose.r4s.yml
    docker/.env
  </read_first>
  <behavior>
    - 在 Mac 上构建 noda-ops 镜像（docker build）
    - 通过 SSH 管道将镜像传输到 r4s（docker save | ssh docker load）（per D-07）
    - 验证 r4s 上镜像存在且为 ARM64 架构
  </behavior>
  <action>
    **步骤 1: Mac 上构建 noda-ops 镜像**

    从仓库根目录构建（Dockerfile.noda-ops 的 context 是 `..` 即仓库根目录）：
    ```
    docker build -t noda-ops:latest -f deploy/Dockerfile.noda-ops .
    ```

    确认构建成功：
    ```
    docker images noda-ops:latest --format "table {{.Repository}}\t{{.Tag}}\t{{.Size}}\t{{.ID}}"
    ```

    **步骤 2: SSH 管道传输镜像到 r4s（per D-07）**

    使用 SSH 压缩（-C），noda-ops 镜像约 304MB：
    ```
    docker save noda-ops:latest | ssh -C root@$R4S_HOST "docker load"
    ```

    **步骤 3: 验证 r4s 上镜像存在**

    ```
    ssh root@$R4S_HOST "docker images noda-ops --format 'table {{.Repository}}\t{{.Tag}}\t{{.Size}}'"
    ```

    确认架构为 ARM64（aarch64）：
    ```
    ssh root@$R4S_HOST "docker inspect noda-ops:latest --format '{{.Architecture}}'"
    ```
    应返回 "arm64"。
  </action>
  <verify>
    <automated>
      ssh root@$R4S_HOST "docker images noda-ops:latest --format '{{.ID}}'" | grep -q '.' && echo "IMAGE_EXISTS"
    </automated>
  </verify>
  <done>
    - noda-ops:latest 镜像在 Mac 上构建成功
    - 镜像已通过 SSH 管道传输到 r4s
    - r4s 上 docker images 显示 noda-ops:latest，架构为 arm64
  </done>
</task>

<task type="auto">
  <name>Task 2: r4s 上启动 noda-ops 并验证全部基础设施服务</name>
  <files></files>
  <read_first>
    docker/docker-compose.yml
    docker/docker-compose.prod.yml
    docker/docker-compose.r4s.yml
    docker/.env
  </read_first>
  <behavior>
    - 在 r4s 上通过 Docker Compose 启动 noda-ops 容器
    - 等待 noda-ops 健康检查通过（pg_isready 连接 PG）
    - 验证 noda-ops 内 Cloudflare Tunnel 状态
    - 验证 noda-ops 内 supervisord 服务运行
    - 最终验证：所有 4 个基础设施容器（PG + Keycloak + Nginx + noda-ops）在 r4s 上运行且健康
    - 验证所有容器都在 noda-network 网络中
  </behavior>
  <action>
    **步骤 1: r4s 上启动 noda-ops 容器**

    noda-ops 通过 Docker Compose 启动（非 profiles: disabled）：
    ```
    ssh root@$R4S_HOST "cd $R4S_REPO_PATH && \
      docker compose -f docker/docker-compose.yml \
        -f docker/docker-compose.prod.yml \
        -f docker/docker-compose.r4s.yml \
      up -d noda-ops"
    ```

    注意：noda-ops 在 docker-compose.yml 中 `depends_on: postgres`，但 PG 已经在运行（Plan 01），不会触发 PG 重启。

    **步骤 2: 等待 noda-ops 健康检查通过**

    noda-ops 健康检查是 `pg_isready -h noda-infra-postgres-prod`：
    ```
    for i in $(seq 1 6); do
      status=$(ssh root@$R4S_HOST "docker inspect --format='{{.State.Health.Status}}' noda-ops 2>/dev/null || echo 'unknown'")
      echo "Attempt $i: $status"
      if [ "$status" = "healthy" ]; then break; fi
      sleep 10
    done
    ```

    **步骤 3: 验证 noda-ops 内服务状态**

    检查 supervisord 状态（noda-ops 使用 supervisord 管理 crond 和 cloudflared）：
    ```
    ssh root@$R4S_HOST "docker exec noda-ops supervisorctl status"
    ```
    应显示 crond 和 cloudflared（如果有）为 RUNNING 状态。

    **步骤 4: 验证 Cloudflare Tunnel 状态**

    检查 cloudflared 日志：
    ```
    ssh root@$R4S_HOST "docker exec noda-ops cat /var/log/supervisor/cloudflared*.log 2>/dev/null | tail -20"
    ```

    或检查 supervisord 日志：
    ```
    ssh root@$R4S_HOST "docker logs --tail 30 noda-ops 2>&1 | grep -i 'cloudflare\\|tunnel\\|registered'"
    ```

    注意：此时 Cloudflare Tunnel 仍在 Mac 上运行（未迁移到 r4s）。r4s 上启动 noda-ops 时如果 CLOUDFLARE_TUNNEL_TOKEN 环境变量存在，cloudflared 会尝试注册新 Tunnel 连接。这不会影响 Mac 上的现有 Tunnel（Cloudflare 支持同一 Token 多个连接）。但如果担心冲突，可以在 Phase 61 迁移 Tunnel 时不启动 r4s 的 cloudflared。当前阶段只要 cloudflared 进程在运行即可。

    **步骤 5: 验证全部基础设施容器状态**

    ```
    ssh root@$R4S_HOST "docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'"
    ```

    应显示 4 个容器全部运行：
    - noda-infra-postgres-prod
    - noda-infra-keycloak
    - noda-infra-nginx
    - noda-ops

    **步骤 6: 验证所有容器在 noda-network 中**

    ```
    ssh root@$R4S_HOST "docker network inspect noda-network --format '{{range .Containers}}{{.Name}} {{end}}'"
    ```
    应包含全部 4 个容器名。

    **步骤 7: 端到端验证摘要**

    执行综合健康检查：
    ```
    # PG 健康
    ssh root@$R4S_HOST "docker exec noda-infra-postgres-prod pg_isready -U postgres"
    # Keycloak 健康（TCP 8080）
    ssh root@$R4S_HOST "docker exec noda-infra-keycloak bash -c 'echo > /dev/tcp/localhost/8080' 2>/dev/null && echo KC_OK || echo KC_FAIL"
    # Nginx 健康
    ssh root@$R4S_HOST "curl -s -o /dev/null -w '%{http_code}' http://localhost:8080/"
    # Nginx → Keycloak 代理
    ssh root@$R4S_HOST "curl -s -o /dev/null -w '%{http_code}' http://localhost:8080/auth/"
    # noda-ops 健康
    ssh root@$R4S_HOST "docker inspect --format='{{.State.Health.Status}}' noda-ops"
    ```
  </action>
  <verify>
    <automated>
      ssh root@$R4S_HOST "docker ps --format '{{.Names}}' | grep -c 'noda-infra-postgres-prod\\|noda-infra-keycloak\\|noda-infra-nginx\\|noda-ops'" | grep -q "4" && echo "ALL_4_CONTAINERS_RUNNING" && \
      ssh root@$R4S_HOST "docker network inspect noda-network --format '{{range .Containers}}{{.Name}} {{end}}'" | grep -c 'noda-infra-postgres-prod\\|noda-infra-keycloak\\|noda-infra-nginx\\|noda-ops' | grep -q "4" && echo "ALL_IN_NETWORK"
    </automated>
  </verify>
  <done>
    - noda-ops 容器在 r4s 上运行且健康检查通过
    - noda-ops 内 supervisord 服务（crond、cloudflared）运行中
    - noda-ops 能连接 r4s PG 数据库
    - 全部 4 个基础设施容器（PG + Keycloak + Nginx + noda-ops）在 r4s 上运行
    - 全部 4 个容器都在 noda-network 网络中
    - Nginx → Keycloak 反向代理链路正常
  </done>
