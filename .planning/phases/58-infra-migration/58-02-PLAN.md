<task type="auto">
  <name>Task 1: r4s 上启动 Keycloak 并验证</name>
  <files></files>
  <read_first>
    docker/docker-compose.prod.yml
    docker/docker-compose.r4s.yml
    docker/.env
  </read_first>
  <behavior>
    - 确认 r4s PG 容器健康状态为 healthy
    - 在 r4s 上通过 docker run 启动 Keycloak 容器（profiles: disabled，不通过 compose 启动）
    - Keycloak 使用 docker-compose.prod.yml 中定义的相同环境变量
    - KC_DB_URL 中主机名使用 noda-infra-postgres-prod（Docker 内部 DNS）
    - 内存限制 640M（per r4s overlay）
    - 等待 Keycloak 健康检查通过（TCP 8080）
    - 验证 Keycloak 能正确连接 PG 中的 keycloak 数据库
    - 验证 Keycloak realm 配置完整（通过 admin API 或日志检查）
  </behavior>
  <action>
    **步骤 1: 确认 PG 健康状态**

    ```
    ssh root@$R4S_HOST "docker inspect --format='{{.State.Health.Status}}' noda-infra-postgres-prod"
    ```
    必须返回 "healthy" 才能继续。

    **步骤 2: 从 .env 读取必要的环境变量值**

    从 Mac 的 docker/.env 文件读取以下变量的值（用于 docker run -e 参数）：
    - POSTGRES_USER
    - POSTGRES_PASSWORD
    - KEYCLOAK_ADMIN_USER
    - KEYCLOAK_ADMIN_PASSWORD
    - SMTP_HOST、SMTP_PORT、SMTP_FROM、SMTP_USER、SMTP_PASSWORD（如果已配置）

    **步骤 3: 在 r4s 上 docker run 启动 Keycloak**

    Keycloak 不通过 Docker Compose 启动（profiles: disabled），使用 docker run：
    ```
    ssh root@$R4S_HOST "docker run -d \
      --name noda-infra-keycloak \
      --network noda-network \
      --restart unless-stopped \
      --memory 640m \
      -e KC_DB=postgres \
      -e KC_DB_URL='jdbc:postgresql://noda-infra-postgres-prod:5432/keycloak' \
      -e KC_DB_USERNAME=$POSTGRES_USER \
      -e KC_DB_PASSWORD=$POSTGRES_PASSWORD \
      -e KC_HOSTNAME='https://auth.noda.co.nz' \
      -e KC_HOSTNAME_STRICT=false \
      -e KC_HTTP_ENABLED=true \
      -e KC_PROXY=edge \
      -e KC_PROXY_HEADERS=xforwarded \
      -e KC_FRONTEND_URL='https://auth.noda.co.nz' \
      -e KC_HEALTH_ENABLED=true \
      -e KEYCLOAK_ADMIN=$KEYCLOAK_ADMIN_USER \
      -e KEYCLOAK_ADMIN_PASSWORD=$KEYCLOAK_ADMIN_PASSWORD \
      -v $R4S_REPO_PATH/docker/services/keycloak/themes:/opt/keycloak/themes/noda:ro \
      quay.io/keycloak/keycloak:26.2.3 \
      start --hostname-strict=false --proxy-headers=xforwarded"
    ```

    注意：KC_DB_URL 使用 `noda-infra-postgres-prod` 而非 `postgres`（compose service name），因为 Keycloak 不在 compose 网络中，需要用容器名或网络别名。但 docker run 加入 noda-network 后，可通过 compose 服务名 `postgres` 解析。验证：如果 `postgres` DNS 不通，改用 `noda-infra-postgres-prod`（容器名）。

    **步骤 4: 等待 Keycloak 启动和健康检查**

    Keycloak 启动需要 30-60 秒：
    ```
    # 轮询健康检查
    for i in $(seq 1 12); do
      status=$(ssh root@$R4S_HOST "docker inspect --format='{{.State.Health.Status}}' noda-infra-keycloak 2>/dev/null || echo 'unknown'")
      echo "Attempt $i: $status"
      if [ "$status" = "healthy" ]; then break; fi
      sleep 10
    done
    ```

    如果 Keycloak 没有内置健康检查（docker run 未定义 healthcheck），手动检查：
    ```
    ssh root@$R4S_HOST "docker exec noda-infra-keycloak echo > /dev/tcp/localhost/8080 2>/dev/null && echo OK || echo FAIL"
    ```
    或检查日志确认 "started" 关键字：
    ```
    ssh root@$R4S_HOST "docker logs --tail 20 noda-infra-keycloak 2>&1 | grep -i 'started'"
    ```

    **步骤 5: 验证 Keycloak 连接 PG**

    检查 Keycloak 日志中无数据库连接错误：
    ```
    ssh root@$R4S_HOST "docker logs noda-infra-keycloak 2>&1 | grep -i 'error\\|exception\\|connection' | head -20"
    ```

    如果出现连接错误，检查：
    1. Keycloak 是否在 noda-network 中：`ssh root@$R4S_HOST "docker inspect --format='{{range .NetworkSettings.Networks}}{{.NetworkID}}{{end}}' noda-infra-keycloak"`
    2. DNS 解析是否正确：`ssh root@$R4S_HOST "docker exec noda-infra-keycloak nslookup noda-infra-postgres-prod 2>/dev/null || echo DNS_FAIL"`

    **步骤 6: 验证 Keycloak realm 配置**

    通过 r4s 内部 curl 验证 Keycloak admin API 可达：
    ```
    ssh root@$R4S_HOST "docker exec noda-infra-keycloak curl -s http://localhost:8080/health"
    ```

    或验证 realm 存在（通过直接 HTTP）：
    ```
    ssh root@$R4S_HOST "docker exec noda-infra-keycloak curl -s http://localhost:8080/realms/noda/.well-known/openid-configuration | head -5"
    ```

    如果 curl 不在 Keycloak 容器中，从同网络的另一个容器测试，或直接检查日志中 "noda" realm 加载记录。
  </action>

  <behavior>
    - 在 r4s 上通过 Docker Compose 启动 Nginx 容器
    - Nginx 配置文件通过 bind mount 从 r4s 仓库挂载
    - r4s overlay 映射端口 8080:80、8081:81、8443:443（避免与 iStoreOS 冲突）
    - 验证 Nginx 能正确加载配置（无语法错误）
    - 验证 Nginx 监听端口正常
    - 验证 Nginx → Keycloak 反向代理链路（auth 路径）
    - 注意：findclass-ssr upstream 尚未就绪（Phase 59 迁移），Nginx 会报 upstream 不可达但不会崩溃
  </behavior>
  <action>
    **步骤 1: 确认 Nginx 配置文件在 r4s 上存在**

    Nginx 的 bind mount 依赖仓库中的配置文件：
    ```
    ssh root@$R4S_HOST "ls -la $R4S_REPO_PATH/config/nginx/conf.d/default.conf"
    ssh root@$R4S_HOST "ls -la $R4S_REPO_PATH/config/nginx/snippets/"
    ssh root@$R4S_HOST "ls -la $R4S_REPO_PATH/config/nginx/nginx.conf"
    ```

    如果文件不存在，说明仓库未完整 clone，需要 `git pull` 或重新 clone。

    **步骤 2: 通过 Docker Compose 启动 Nginx**

    ```
    ssh root@$R4S_HOST "cd $R4S_REPO_PATH && \
      docker compose -f docker/docker-compose.yml \
        -f docker/docker-compose.prod.yml \
        -f docker/docker-compose.r4s.yml \
      up -d nginx"
    ```

    **步骤 3: 验证 Nginx 启动和配置加载**

    检查容器状态：
    ```
    ssh root@$R4S_HOST "docker ps --filter name=noda-infra-nginx --format 'table {{.Names}}\t{{.Status}}'"
    ```

    检查 Nginx 配置语法（通过 docker exec）：
    ```
    ssh root@$R4S_HOST "docker exec noda-infra-nginx nginx -t"
    ```
    应返回 "syntax is ok" 和 "test is successful"。

    **步骤 4: 验证 Nginx 端口监听**

    ```
    ssh root@$R4S_HOST "curl -s -o /dev/null -w '%{http_code}' http://localhost:8080/"
    ```
    应返回非零 HTTP 状态码（可能是 502 Bad Gateway，因为 findclass-ssr 未迁移，但说明 Nginx 在响应）。

    **步骤 5: 验证 Nginx → Keycloak 代理链路**

    ```
    ssh root@$R4S_HOST "curl -s -o /dev/null -w '%{http_code}' http://localhost:8080/auth/"
    ```
    应返回 200 或 302（Keycloak admin 控制台或登录页面）。

    如果返回 502，检查：
    1. Nginx 是否在 noda-network 中
    2. upstream-keycloak.conf 中的 upstream 地址是否正确（应该是 `noda-infra-keycloak:8080` 或 `keycloak:8080`）
    3. Keycloak 容器是否在同一网络中

    注意 upstream-findclass.conf 和 upstream-preprod.conf 指向尚未迁移的应用容器，Nginx 日志中可能有 "host not found in upstream" 警告，但不影响已启动服务的代理。如果 Nginx 因此无法启动，需要临时注释掉这些 upstream（但更可能是 Nginx 仅在请求时才报错，不影响启动）。
  </action>
  <verify>
    <automated>
      ssh root@$R4S_HOST "docker exec noda-infra-nginx nginx -t" && \
      ssh root@$R4S_HOST "curl -s -o /dev/null -w '%{http_code}' http://localhost:8080/auth/" && \
      echo "NGINX_OK"
    </automated>
  </verify>
  <done>
    - Nginx 容器在 r4s 上运行
    - Nginx 配置语法检查通过（nginx -t）
    - 端口 8080/8081/8443 正常监听
    - Nginx → Keycloak 反向代理可达（/auth/ 路径返回 200 或 302）
    - Nginx 在 noda-network 网络中
  </done>
