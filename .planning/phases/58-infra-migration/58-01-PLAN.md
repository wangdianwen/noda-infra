  <action>
    按以下顺序执行（所有 SSH 命令中使用 $R4S_HOST 变量，executor 从实际环境获取）：

    **阶段 1: 获取 Mac 数据基准线（在迁移前执行，保存输出用于对比）**

    获取每个数据库的表行数统计：
    ```
    for db in keycloak noda_prod noda_preprod noda_agent; do
      echo "=== $db ==="
      docker exec noda-infra-postgres-prod psql -U postgres -d "$db" -c "
        SELECT schemaname || '.' || tablename as table_name,
               (xpath('/row/cnt/text()', query_to_xml(format('SELECT count(*) as cnt FROM %I.%I', schemaname, tablename), false, true, '')))[1]::text::int as row_count
        FROM pg_tables
        WHERE schemaname NOT IN ('pg_catalog', 'information_schema')
        ORDER BY schemaname, tablename;"
    done
    ```

    获取序列值统计：
    ```
    for db in keycloak noda_prod noda_preprod noda_agent; do
      echo "=== $db sequences ==="
      docker exec noda-infra-postgres-prod psql -U postgres -d "$db" -c \
        "SELECT sequencename, last_value FROM pg_sequences ORDER BY sequencename;"
    done
    ```

    保存输出到临时文件，用于后续对比。

    **阶段 2: Mac 上停服（per D-03, D-11）**

    停止所有依赖 PG 的容器：
    ```
    docker stop noda-infra-keycloak noda-ops noda-infra-nginx
    ```
    注意：findclass-ssr 容器如果运行也应停止（`docker ps --filter name=findclass` 确认），停止顺序无严格要求。

    **阶段 3: Mac 上执行完整备份（per D-04）**

    触发 noda-ops 内的备份脚本（如果 noda-ops 已停止，则直接用 docker exec PG 容器执行 pg_dump）：
    ```
    docker exec noda-infra-postgres-prod /app/backup/backup-postgres.sh
    ```
    如果 noda-ops 已停止导致备份脚本不可用，使用手动 pg_dump：
    ```
    docker exec noda-infra-postgres-prod pg_dumpall -U postgres -Fc > /tmp/pre-migration-backup.dump
    ```
    确认备份文件已生成。

    **阶段 4: r4s 上部署 .env 文件（per D-08）**

    通过 SSH 管道将 Mac 的 .env 文件传输到 r4s：
    ```
    cat docker/.env | ssh root@$R4S_HOST "cat > $R4S_REPO_PATH/docker/.env"
    ```
    其中 $R4S_REPO_PATH 是 r4s 上 noda-infra 仓库的路径（Task 0 中确认的路径）。

    **阶段 5: r4s 上启动空 PostgreSQL 容器（per D-05）**

    ```
    ssh root@$R4S_HOST "cd $R4S_REPO_PATH && \
      docker compose -f docker/docker-compose.yml \
        -f docker/docker-compose.prod.yml \
        -f docker/docker-compose.r4s.yml \
        up -d postgres"
    ```

    等待 PG 健康检查通过（轮询直到 healthy）：
    ```
    ssh root@$R4S_HOST "docker inspect --format='{{.State.Health.Status}}' noda-infra-postgres-prod"
    ```
    重复检查直到返回 "healthy"。

    **阶段 6: r4s PG 中创建数据库和角色（Pitfall 1 规避）**

    noda_prod 由 POSTGRES_DB 环境变量自动创建，其余 3 个数据库手动创建：
    ```
    for db in keycloak noda_preprod noda_agent; do
      ssh root@$R4S_HOST "docker exec -i noda-infra-postgres-prod psql -U postgres -c 'CREATE DATABASE $db;'"
    done
    ```

    创建 preprod_app 角色（RESEARCH.md Runtime State Inventory 确认存在此角色）：
    ```
    ssh root@$R4S_HOST "docker exec -i noda-infra-postgres-prod psql -U postgres -c \"CREATE ROLE preprod_app WITH LOGIN PASSWORD '${POSTGRES_PASSWORD}';\""
    ssh root@$R4S_HOST "docker exec -i noda-infra-postgres-prod psql -U postgres -c 'GRANT ALL PRIVILEGES ON DATABASE noda_preprod TO preprod_app;'"
    ```
    其中 POSTGRES_PASSWORD 从 Mac 的 docker/.env 文件中读取。

    **阶段 7: SSH 管道流式迁移 4 个数据库（per D-01, D-02）**

    逐数据库迁移，使用 -Fc 自定义格式（压缩、支持并行恢复）：
    ```
    for db in noda_prod keycloak noda_preprod noda_agent; do
      echo "=== Migrating $db ==="
      docker exec noda-infra-postgres-prod \
        pg_dump -U postgres -Fc "$db" | \
        ssh root@$R4S_HOST \
        "docker exec -i noda-infra-postgres-prod pg_restore -U postgres -d $db --no-owner --no-privileges"
      echo "=== $db done ==="
    done
    ```

    注意 `--no-owner --no-privileges` 参数：因为源端和目标端都是 postgres 超级用户，跳过 owner/grant 避免跨容器权限不匹配问题（RESEARCH.md A7）。

    如果某个数据库的 pg_restore 报错 "already exists"，这是因为 POSTGRES_DB 创建的 noda_prod 可能已有默认对象。使用 `--clean --if-exists` 参数重试即可。

    **阶段 8: 数据完整性验证（per D-06）**

    在 r4s 上执行与阶段 1 相同的查询，对比结果：
    ```
    for db in keycloak noda_prod noda_preprod noda_agent; do
      echo "=== $db ==="
      ssh root@$R4S_HOST "docker exec -i noda-infra-postgres-prod psql -U postgres -d '$db' -c \"
        SELECT schemaname || '.' || tablename as table_name,
               (xpath('/row/cnt/text()', query_to_xml(format('SELECT count(*) as cnt FROM %I.%I', schemaname, tablename), false, true, '')))[1]::text::int as row_count
        FROM pg_tables
        WHERE schemaname NOT IN ('pg_catalog', 'information_schema')
        ORDER BY schemaname, tablename;\""
    done
    ```

    对比序列值：
    ```
    for db in keycloak noda_prod noda_preprod noda_agent; do
      echo "=== $db sequences ==="
      ssh root@$R4S_HOST "docker exec -i noda-infra-postgres-prod psql -U postgres -d '$db' -c \
        \"SELECT sequencename, last_value FROM pg_sequences ORDER BY sequencename;\""
    done
    ```

    对比结果：每个数据库的表数量、每表行数、序列值必须与 Mac 基准线完全一致。

    **阶段 9: 确认 Mac 旧容器保留状态（per D-12）**

    ```
    docker ps -a --filter status=exited --format "table {{.Names}}\t{{.Status}}"
    ```
    确认 keycloak、noda-ops、nginx 容器处于 Exited 状态且未被删除。
