# Plan 62-02: 回滚方案验证

## 目标

确认如果 r4s 出现严重故障，可以快速将服务切回 Mac 运行，保证业务连续性。

## 前置条件

- Plan 62-01 全链路验证通过
- 当前 Mac Jenkins 可用

## 任务

### T1: Mac 回滚环境检查
确认 Mac 仍具备运行所有服务的能力：

1. **Docker 环境**: `docker --version` + `docker compose version`
2. **Docker 网络**: `docker network ls | grep noda-network` 确认存在
3. **Docker 镜像**: 检查关键镜像是否保留
   - `docker images | grep postgres`
   - `docker images | grep nginx`
   - `docker images | grep noda-ops`
   - `docker images | grep keycloak`
   - `docker images | grep noda-apps`
4. **Docker Compose 文件**: 确认 `docker/docker-compose.yml` + `docker/docker-compose.prod.yml` 存在且可用
5. **环境变量**: 确认 `docker/.env` 存在且包含必要密钥
6. **端口可用**: 确认 80/443/5432/8080 端口未被占用

### T2: Cloudflare Tunnel 回滚测试
验证 Cloudflare Tunnel 可以切回 Mac：

1. **当前 Tunnel 配置**: 记录当前 Cloudflare Tunnel 指向 r4s 的配置
2. **Mac cloudflared 可用性**: 确认 Mac 上 cloudflared 二进制存在
3. **Tunnel token**: 确认 `CLOUDFLARE_TUNNEL_TOKEN` 在 Mac docker/.env 中可用
4. **理论回滚步骤文档化**: 写出具体回滚命令序列（不实际执行）：
   ```
   1. r4s: docker stop noda-ops (停止 r4s 上的 Tunnel)
   2. Mac: docker compose up -d noda-ops (启动 Mac 上的 Tunnel)
   3. 验证: curl https://class.noda.co.nz/api/health
   ```

### T3: Mac 数据库回滚测试
验证如果 r4s PostgreSQL 不可用，Mac 可以恢复到最近备份：

1. **Mac PostgreSQL 可启动**: `docker compose up -d postgres` 确认能启动
2. **最新备份可下载**: 从 B2 下载最新备份文件到 Mac
3. **恢复测试**（只读验证，不实际恢复）:
   - `pg_restore --list <backup_file>` 确认备份文件可读
   - 计算恢复预估时间
4. **文档化回滚步骤**

### T4: 回滚 Runbook 编写
创建 `docs/ROLLBACK-RUNBOOK.md`，包含：

1. **触发条件**: 什么情况下需要回滚
2. **回滚步骤**（按服务分）:
   - Cloudflare Tunnel 回切
   - PostgreSQL 恢复
   - 应用服务回切
   - Keycloak 回切
3. **预期恢复时间**: 每个步骤的预估耗时
4. **验证清单**: 回滚后需要验证的项目
5. **数据一致性**: 回滚期间和回滚后的数据一致性注意事项

### T5: 回滚演练（Dry Run）
不实际切换，但模拟回滚步骤：

1. 在 Mac 上验证 docker compose config 能正确解析（不启动）
2. 在 Mac 上验证手动部署脚本能正确执行到 dry-run 模式
3. 确认所有依赖（镜像、密钥、网络）齐全

## 验证标准

- [ ] Mac Docker 环境完整可用
- [ ] Cloudflare Tunnel 回滚步骤已文档化且可行
- [ ] PostgreSQL 备份可在 Mac 恢复
- [ ] ROLLBACK-RUNBOOK.md 已创建
- [ ] Dry run 通过（不实际切换）

## 安全约束

**不实际执行回滚切换** — 只验证回滚能力，不中断生产服务。
