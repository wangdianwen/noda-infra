## 接口定义

### Cloudflare Tunnel 配置（来自 `config.yml`）

```yaml
tunnel: 9cab5df3-a546-48fb-9dc5-eacb48c56ff8
version: 2
loglevel: info

ingress:
  - hostname: noda.co.nz
    service: http://noda-nginx:80
  - hostname: auth.noda.co.nz
    service: http://noda-nginx:80
  - hostname: localhost.noda.co.nz
    service: http://noda-nginx:80
  - hostname: health.noda.co.nz
    service: http://noda-nginx:80
  - service: http_status:404
```

### Nginx Pre-Prod 路由（来自 Phase 54-01）

4 个 pre-prod server blocks 已在 `default.conf` 中创建：
- `pre.class.noda.co.nz` → `$findclass_preprod_upstream`（当前无后端，返回 502）
- `pre.auth.noda.co.nz` → `$auth_app_preprod_upstream`（Auth App，无后端返回 502）+ `$keycloak_upstream`（Keycloak，返回登录页）
- `pre.noda.co.nz` → `$www_preprod_upstream`（当前无后端，返回 502）
- `pre.admin.noda.co.nz` → `$admin_preprod_upstream`（当前无后端，返回 502）

## 任务

### Task 1: 添加 Cloudflare DNS 记录（Checkpoint: Human-Action）

**类型：** `checkpoint:human-action`

**需要人工操作的原因：** Cloudflare DNS 记录无法通过 CLI/API 自动添加（需要 Cloudflare API Token，当前未配置）。

**操作步骤：**

1. **登录 Cloudflare Dashboard**
   - 访问 https://dash.cloudflare.com
   - 登录账号
   - 选择 `noda.co.nz` 域名

2. **添加 4 个 CNAME 记录**
   - 导航到 **DNS → Records**
   - 点击 **Add record** 按钮
   - 添加以下 4 个记录：

     | Type | Name | Target | Proxy status | TTL |
     |------|------|--------|--------------|-----|
     | CNAME | `pre.class` | `noda-ops.noda.co.nz` | Proxied（橙色云） | Auto |
     | CNAME | `pre.auth` | `noda-ops.noda.co.nz` | Proxied（橙色云） | Auto |
     | CNAME | `pre` | `noda-ops.noda.co.nz` | Proxied（橙色云） | Auto |
     | CNAME | `pre.admin` | `noda-ops.noda.co.nz` | Proxied（橙色云） | Auto |

   - **注意：** `noda-ops.noda.co.nz` 是当前已存在的 A 记录（指向服务器 IP）
   - **Proxy status 必须是 Proxied**（橙色云图标），不能是 DNS only（灰色云）

3. **验证 DNS 记录**
   - 确认 4 个记录显示在 DNS 列表中
   - 确认 Proxy status 列显示橙色云图标（Proxied）
   - 记录创建完成后，等待几分钟（DNS 传播）

**如何验证：**
```bash
# 等待 DNS 传播（1-2 分钟）
sleep 120

# 验证 DNS 解析
dig pre.class.noda.co.nz +short
# 预期输出：Cloudflare IP（例如 172.6x.xxx.xxx）

dig pre.auth.noda.co.nz +short
# 预期输出：Cloudflare IP

dig pre.noda.co.nz +short
# 预期输出：Cloudflare IP

dig pre.admin.noda.co.nz +short
# 预期输出：Cloudflare IP
```

**恢复信号：**
确认以下内容后输入 "approved"：
- 4 个 CNAME 记录已添加到 Cloudflare Dashboard
- Proxy status 都是 Proxied（橙色云）
- `dig` 命令返回 Cloudflare IP（非服务器真实 IP）

**如果 DNS 未生效：** 检查 Cloudflare Dashboard 的记录详情，确认：
- Type 是 CNAME（不是 A 记录）
- Name 字段正确（`pre.class`、`pre.auth`、`pre`、`pre.admin`）
- Target 是 `noda-ops.noda.co.nz`（或现有的 A 记录名称）
- Proxy status 是 Proxied（橙色云）

### Task 2: 扩展 Cloudflare Tunnel 配置

**文件：** `config/cloudflare/config.yml`

**动作：**
1. 在 `ingress:` 块中的 `health.noda.co.nz` 规则之后、默认规则（`- service: http_status:404`）之前，添加 4 条 pre-prod 域名规则：

   ```yaml
   # Pre-prod 域名
   - hostname: pre.class.noda.co.nz
     service: http://noda-nginx:80
   - hostname: pre.auth.noda.co.nz
     service: http://noda-nginx:80
   - hostname: pre.noda.co.nz
     service: http://noda-nginx:80
   - hostname: pre.admin.noda.co.nz
     service: http://noda-nginx:80
   ```

2. 确保默认规则（`- service: http_status:404`）仍在最后位置（ingress 规则按顺序匹配）
3. 保持现有 prod 域名规则不变
4. 为 pre-prod 域名添加注释（区分 prod 和 pre-prod）

**避免：**
- 不要删除或修改现有的 prod 域名 ingress 规则
- 不要移动默认规则（`- service: http_status:404`）的位置（必须在最后）
- 不要修改 `tunnel:` 或 `version:` 字段

**为什么：**
- Pre-prod 域名需要通过 Tunnel 路由到 `noda-nginx:80`（与 prod 相同）
- 默认规则必须是最后一条（作为兜底，返回 404）
- 修改 Tunnel ID 或 version 会导致 Tunnel 连接失败

**验证：**

```bash
# 预期输出：无错误（exit code 0）
```

**完成标准：**
- `config.yml` 包含 4 个 pre-prod 域名的 ingress 规则
- 所有 pre-prod 规则指向 `http://noda-nginx:80`
- 默认规则（`http_status:404`）仍在最后

## 威胁模型

### 信任边界

| 边界 | 描述 |
|------|------|
| 外部用户 → Cloudflare → Cloudflare Tunnel | TLS 终止在 Cloudflare，Tunnel 通过 QUIC 协议连接到 noda-ops 容器 |
| Cloudflare Tunnel → Nginx | 内部 HTTP 连接（`http://noda-nginx:80`），无加密 |
| Nginx → Pre-prod 后端容器 | 当前无后端容器（Phase 55 创建），Nginx 返回 502 |

### STRIDE 威胁登记表

| 威胁 ID | 类别 | 组件 | 处置 | 缓解措施 |
|---------|------|------|------|----------|
| T-54-06 | 篡改 | Cloudflare DNS 记录 | 接受 | DNS 记录在 Cloudflare Dashboard 管理，修改需要 Cloudflare 账号权限 |
| T-54-07 | 拒绝服务 | Tunnel 配置错误导致容器退出 | 缓解 | 修改 config.yml 前验证 YAML 语法（`cloudflared config validate`） |
| T-54-08 | 信息泄露 | Pre-prod 域名暴露内部服务 | 接受 | Pre-prod 与 prod 使用相同的网络架构，无额外的安全边界 |
| T-54-09 | 权限提升 | Pre-prod 域名访问 prod 后端 | 缓解 | 使用独立的 upstream 变量（`_preprod_` 前缀），Task 5 验证无冲突 |
